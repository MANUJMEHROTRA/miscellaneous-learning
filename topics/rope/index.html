01 / Before RoPE: attention basics

First, what is attention trying to calculate?

A language model turns each token into vectors. For one attention head, it makes a query (what this token is looking for) and a key (what another token offers). Their dot product is a compatibility score.

1

Make query and key

Learned linear layers turn token representations into vectors.

qm = WQxm
kn = WKxn
→
2

Compare them

A dot product is large when the vectors point in similar directions.

score = qmTkn
→
3

Use the scores

Softmax turns scores into weights. The model uses them to mix value vectors.

weights = softmax(scores / √dh)
↳

The missing ingredient: without position information, attention's comparison doesn't inherently know which token came first. RoPE changes the query–key comparison so it carries position information too. It does not replace the rest of attention.

ONE COMMON APPROACH

Add a position vector: combine a token representation and a positional vector before later layers process it.

xp + positionp
RoPE'S APPROACH

Rotate query and key pairs: apply position-dependent rotations to the projected query and key. Their dot product then reflects their relative offset.

Rmq   and   Rnk

02 / RoPE intuition

Position, encoded as a turn.

Attention needs to know not just what a token says, but where it sits. RoPE (Rotary Position Embedding) injects position by rotating pairs of query and key features by position-dependent angles.

A

Pair up features

Take two coordinates from a query or key vector. Treat them as a point on a plane.

q
B

Rotate by position

At token position p, rotate that point by p times this pair's frequency.

↻p · ω
C

Compare the turns

The query–key dot product now depends on their relative positions, not just their content.

R(m)TR(n) = R(n − m)
↳

Useful intuition: different feature pairs turn at different speeds. Fast turns help distinguish nearby positions; slow turns change gradually over longer distances.

03 / Pen-and-paper example

Calculate one RoPE attention score by hand.

We will use just two coordinates—the smallest possible RoPE example. The numbers are deliberately friendly. Grab paper and follow the rotations before revealing each arithmetic step.

OUR TOY SETUP
Query contentq = (1, 0)
Key contentk = (1, 0)
One-pair frequencyω = π/6 radians per token
Token positionsquery m = 1, key n = 3

Both content vectors start pointing right. RoPE turns each by its position multiplied by ω. Ignore softmax and the multi-head scaling for this toy calculation—we are finding just one pair's raw dot-product contribution.

STEP 1

Write down the rotation rule

Rotating the unit vector (1, 0) by angle α gives (cos α, sin α).

R(α)(1, 0) = (cos α, sin α)
Why is that true?

Multiply the rotation matrix by the vector: [cos α −sin α; sin α cos α] · [1; 0] = [cos α; sin α]. The second column is multiplied by zero.

STEP 2

Rotate the query at position 1

Its angle is mω = 1 · π/6 = π/6 (30°).

q1 = (cos π/6, sin π/6) = (√3/2, 1/2)
Check the exact trig values

On the 30°–60°–90° triangle, cos 30° = √3/2 and sin 30° = 1/2.

STEP 3

Rotate the key at position 3

Its angle is nω = 3 · π/6 = π/2 (90°).

k3 = (cos π/2, sin π/2) = (0, 1)
Check the exact trig values

A 90° rotation takes (1, 0) straight up: cos 90° = 0 and sin 90° = 1.

STEP 4

Take their dot product

Multiply matching coordinates, then add.

(√3/2) · 0 + (1/2) · 1 = 1/2
So what was the point?

The position-aware query–key score for this pair is 1/2. It is not "the distance" by itself: it depends both on the query/key content directions and on how far apart their positions are.

THE KEY EXPERIMENT

Move both tokens together. Does the score change?

Shift positions (1, 3) to (11, 13). The separation is still 2. For the same unit vectors, the angles are 11π/6 and 13π/6.

Work out the shifted vectors and compare

q11 = (cos 11π/6, sin 11π/6) = (√3/2, −1/2). k13 = (cos 13π/6, sin 13π/6) = (√3/2, 1/2), since 13π/6 = 2π + π/6. Their dot product is (√3/2)(√3/2) + (−1/2)(1/2) = 3/4 − 1/4 = 1/2. Same score: only the relative offset changed the result.

TRY A POSITION PAIR

Keep q = k = (1, 0) and ω = π/6. Choose positions and calculate the pair score.

Δ = 2; angle difference = 2π/6 = π/3; score = cos(π/3) = 0.500

Try (1, 3), then (11, 13). The positions changed; the offset and score did not.

04 / The proof

Why does the score depend on relative distance?

The worked example showed one numerical case. Now we will prove the same fact for any two query and key vectors in one rotated 2D feature pair.

Step 1: define the rotation

Let the position be p and the pair's frequency be ω. The angle is pω:

Rotation matrix Rp,ω = [ cos(pω)   −sin(pω)
sin(pω)    cos(pω) ]

In the full head: give every pair its own pace

For head dimension d, pair i uses its own frequency ωi. A common RoPE schedule is geometric:

RoPE frequencies ωi = 1 / θ2i/d,   θ = 10,000

Low-index pairs turn quickly; high-index pairs turn slowly. This toy proof needs only one pair. Real attention sums the contributions of many pairs. Implementations can vary the base and scaling strategy.

PROOF: RELATIVE-POSITION IDENTITY

Let q and k be the unrotated query and key for this pair. Their positions are m and n; both use the same frequency ω.

1. Apply RoPE at each positionqm = R(mω)q,   kn = R(nω)k
2. Write their dot productqmTkn = qTR(mω)TR(nω)k
3. A rotation's transpose reverses its angleR(α)T = R(−α)
4. Rotations add their angles when composedR(a)R(b) = R(a + b)
Therefore, only the offset n − m remainsqmTkn = qTR((n − m)ω)k
Why do the two matrix facts hold?

Transposing [cos α −sin α; sin α cos α] gives [cos α sin α; −sin α cos α], which is R(−α). Multiplying R(a)R(b) and using cos(a+b) = cos a cos b − sin a sin b and sin(a+b) = sin a cos b + cos a sin b gives R(a+b).

This proves the identity for one 2D pair. Applying it to every pair gives the full head's score as a sum of content-dependent terms, each encoding the same relative offset at a different frequency.

For a fixed pair, write q and k using their lengths and angles φq, φk. With Δ = n − m: score = ‖q‖ ‖k‖ cos(Δω + φk − φq) Position contributes through Δ, while the content directions contribute through the vector lengths and angles. This is one pair's raw score; a full attention head sums pairs and usually scales the result before softmax.

06 / YaRN & extending context

Stretch carefully, not uniformly.

A model trained for a shorter context has only learned positional patterns over that range. Simply asking it to use much larger positions can push RoPE into unfamiliar phases. YaRN is one method for adapting RoPE to longer contexts without treating every frequency identically.

01

Original RoPE

Keep the training frequencies. At larger positions, rotations travel farther into phase patterns the model may not have learned.

No frequency changes
02

Linear interpolation

Divide positions—or equivalently all frequencies—by the extension factor. This stretches the learned range, but can blur useful short-distance distinctions.

All frequencies slowed equally
03

YaRN

Blend between interpolated and original frequencies across feature dimensions. The transition is designed to preserve some local detail while extending longer-range behavior.

A smooth, frequency-aware blend
SIMPLIFIED FREQUENCY BLEND
ω′i = (1 − ri) · ωi/s + ri · ωi

s is the context extension factor. ri moves smoothly from 0 to 1 across a transition band of frequency dimensions.

Important: production YaRN includes additional choices—such as how transition bounds are set and attention scaling. This lab's blend is a conceptual approximation, not a drop-in implementation or a claim that all models use the same settings.

07 / Training & inference

How does a model get a longer window?

A context limit is not just a slider at inference time. Positional encoding, training exposure, attention implementation, memory, and quality all matter.

01

Pretrain

Learn language and attention patterns on sequences drawn from a training distribution. The maximum training length is not always the same as the final advertised window.

→
02

Extend

Use positional scaling, continued pretraining, long-context fine-tuning, or a combination. Training examples should teach the model to use information across the longer span.

→
03

Serve

Configure inference for that range and provide enough memory/compute. Then evaluate retrieval, reasoning, and quality at different positions—not only whether tokens fit.

!
What about GPT and Gemini?

The exact architectures, positional schemes, training sequence lengths, and extension recipes for current GPT and Gemini models are generally not fully public. Do not assume they use RoPE or YaRN. The methods here describe published techniques and general ways long-context capability can be developed—not confirmed details of those product families.

KEEP IN MIND

A larger context window means more tokens can be processed. It does not guarantee that the model will attend to, retrieve, or reason equally well over every token in that window.
